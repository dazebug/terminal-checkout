PR · 이슈 · 저장소 버튼 · 명령 · main 브랜치 — 터미널 선택과 권한은 Terminal Checkout 앱 설정 창에서

❯ buttons — PR 페이지

PR 페이지 브랜치 옆에 붙는 버튼입니다 (최대 3개). 표시가 버튼의 얼굴이 됩니다 — 이모지 하나든 여러 개든(🌳🤖), 짧은 이름(리뷰, WT)이든 됩니다. 툴팁은 마우스를 올렸을 때 나오고, 프리셋을 고르면 카드가 해당 템플릿으로 채워집니다.

카드 왼쪽 ⠿을 끌거나 ↑ ↓ 키로 순서를 바꿀 수 있습니다 — 이 순서가 GitHub에 붙는 순서이고, 확장 아이콘 클릭은 첫 번째 버튼을 실행합니다. 복제는 비슷한 버튼을 하나 더 만들 때 씁니다 — 사본의 툴팁 뒤에는 (1)처럼 번호가 붙습니다.

쓸 수 있는 변수: {repo} {owner} {number} (PR 번호, 숫자만) {branch} (head — 머지될 브랜치) {base} (base — 머지받을 브랜치) {main} {branch_underbar} (branch의 /를 _로 치환)

버튼은 최대 3개까지 추가할 수 있습니다.

❯ issueButtons — 이슈 페이지

이슈 페이지 상태 배지(Open/Closed) 옆에 붙는 버튼입니다 (최대 3개). PR 버튼과 별도로 설정되며, 이슈 페이지에서는 확장 아이콘 클릭도 이쪽 첫 번째 버튼을 실행합니다. 순서 변경(⠿ 드래그 · ↑ ↓)과 복제는 PR 버튼과 같습니다.

쓸 수 있는 변수: {repo} {owner} {number} (이슈 번호, 숫자만) {main} — 이슈에는 PR의 브랜치가 없어 {branch} 계열과 {base}는 쓸 수 없습니다.

claude 입력에서 !로 시작하면 claude가 그 줄을 셸에서 실행합니다 — 기본 프리셋은 gh로 이슈 본문·코멘트·관련 이슈/PR 번호를 claude에게 읽힙니다.

버튼은 최대 3개까지 추가할 수 있습니다.

❯ repoButtons — 저장소 페이지

저장소 페이지(코드·이슈 목록·Actions 등) 헤더의 저장소 이름 옆에 붙는 버튼입니다 (최대 3개). PR·이슈 버튼과 달리 GitHub의 초록 액션 버튼 모양이라 표시에 Open in Terminal처럼 이름을 넣는 편이 어울립니다. PR·이슈가 아닌 GitHub 페이지에서는 확장 아이콘 클릭도 이쪽 첫 번째 버튼을 실행합니다.

쓸 수 있는 변수: {repo} {owner} {main} — 저장소 페이지에는 PR·이슈 번호도 브랜치도 없어 {number} {branch} 계열과 {base}는 쓸 수 없습니다. {main}은 PR base를 감지할 페이지가 아니라서 아래 main branch 설정으로만 정해집니다 — 기본 브랜치가 master인 리포는 오버라이드를 등록해야 합니다.

버튼은 최대 3개까지 추가할 수 있습니다.

❯ main branch

{main} 결정 순서: 리포별 오버라이드 → PR 페이지 base branch 감지 → 아래 기본값. 이 PR이 실제로 머지될 브랜치를 그대로 쓰려면 오버라이드·기본값을 거치지 않는 {base}를 쓰세요.

이슈·저장소 페이지에는 감지 단계가 없어 오버라이드나 기본값이 그대로 쓰입니다 — 등록하지 않은 master 리포에서는 git checkout {main}이 pathspec 'main' did not match로 끊깁니다.

repository main branch
등록된 오버라이드가 없습니다.

❯ backup — 내보내기 · 가져오기 · 계정 동기화

설정(PR·이슈·저장소 버튼, main 브랜치)은 Chrome 계정 동기화 영역(storage.sync)에 저장됩니다. 이 확장은 ID가 고정되어 있어(manifest key), 같은 Google 계정으로 로그인하고 동기화에서 "확장 프로그램" 항목이 켜진 Chrome끼리는 설정이 자동으로 동기화됩니다. 내보내기/가져오기는 계정을 쓰지 않는 이동이나 파일 백업용입니다.

내보내기는 저장된 설정을 파일로 내려받고, 가져오기는 화면에만 채웁니다 — 저장을 눌러야 반영됩니다.
