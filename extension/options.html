❯ buttons — PR pages

Buttons that sit next to the branch name on a PR page (up to 3). Face is what the button shows — a single emoji, several of them (🌳🤖), or a short name (Review, WT). Tooltip appears on hover, and picking a preset fills the card with that template.

Drag the ⠿ handle on the left of a card, or use the ↑ ↓ keys, to reorder — this is the order the buttons appear in on GitHub, and clicking the extension icon runs the first one. Duplicate is for making another button like an existing one — the copy's tooltip gets a number such as (1) appended.

Available variables: {cd} (move into the repository — the app fills this in from its repository base folder setting, so it works on every page) {repo} {owner} {number} (PR number, digits only) {branch} (head — the branch being merged) {base} (base — the branch it merges into) {main} {branch_underbar} (branch with / replaced by _)

Rewrites of presets we shipped are pre-checked. A command you customized is offered unchecked and marked as a behavior change: only its leading jump is replaced, and the rest of it will now run wherever the new entry clause lands. Every preset starts with {cd}. With no base folder set it is just z {repo}; with one, it falls back to that folder and clones the repository when it isn't there — so a button works even on a repository you have never opened locally.

You can add up to 3 buttons.

❯ issueButtons — Issue pages

Buttons that sit next to the status badge (Open/Closed) on an issue page (up to 3). They are configured separately from the PR buttons, and on an issue page clicking the extension icon runs the first button here. Reordering (drag ⠿, or ↑ ↓) and duplicating work just like they do for PR buttons.

Available variables: {cd} (move into the repository — filled in by the app) {repo} {owner} {number} (issue number, digits only) {main} — an issue has no PR branch, so the {branch} family and {base} are unavailable.

A claude input that starts with ! is typed into claude's shell mode, so the command really runs in that session — the default preset uses gh to put the issue body, its comments and the issues that mention it in front of claude. Consecutive ! inputs are typed as one line.

You can add up to 3 buttons.

❯ repoButtons — Repository pages

Buttons that sit next to the repository name in the header of a repository page (code, issue list, Actions, and so on) — up to 3. Unlike the PR and issue buttons these look like GitHub's green action button, so a name such as Open in Terminal suits the face better than an emoji. On GitHub pages that are neither a PR nor an issue, clicking the extension icon runs the first button here.

Available variables: {cd} (move into the repository — filled in by the app) {repo} {owner} {main} — a repository page has neither a PR or issue number nor a branch, so {number}, the {branch} family, and {base} are unavailable. {main} is resolved from the repository default branch GitHub embeds in the page — a master repository comes out right without an override.

You can add up to 3 buttons.

❯ main branch

How {main} is resolved: per-repository override → detected from the page → the default below. Detection reads the base branch on a PR page, and the repository default branch on repository and issue pages — the setting below is the fallback for when detection fails. To always use the branch a PR will actually be merged into, use {base}, which skips both the override and the default.

repository main branch

❯ backup — export, import, account sync

Settings (PR, issue, and repository buttons, and the main branch) are stored in Chrome's account-synced area (storage.sync). This extension has a fixed ID (the manifest key), so any two Chrome profiles signed in to the same Google account with "Extensions" enabled in sync settings share these settings automatically. Export and import are for moving settings without an account, or for keeping a file backup.

Export downloads the saved settings as a file; import only fills in the form — nothing takes effect until you press Save.

The file also records which generation of the presets it was written against. Importing an older backup offers the same update notice as stored settings do — and since a file may cover only part of your settings, the notice then reviews the whole form, not just the keys the file carried. A backup written by a newer extension is refused rather than half-read; update the extension first.
